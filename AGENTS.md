# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `make ci` — fmt-check + clippy + tests (the local CI gate; keep it green)
- `make pre-commit` — fmt + clippy + tests before committing
- `make clippy` — warnings are denied (`-D warnings`); zero-warning policy
- `make test` / `make test-unit` / `make test-integration`; doc tests run separately: `cargo test --doc --all-features --workspace`
- `make fuzz TARGET=<name>` / `make fuzz-short` — requires nightly + cargo-fuzz 0.13.2 (see Fuzzing)

## Architecture

Rust workspace using Clean Architecture. Crates under `crates/`:

- `domain` — pure business logic; no I/O, no frameworks
- `application` — use cases + port traits; no infrastructure details
- `infrastructure` — sqlx/SQLite, hickory DNS adapters, auth (argon2/webauthn/totp)
- `jobs` — background jobs; `api` — axum REST; `api-pihole` — Pi-hole-compatible API
- `cli` — the only binary crate (package name `ferrous-dns`); wires everything together

Respect the layering: `domain` never imports `infrastructure`. hickory-server/proto are pinned exactly (`=0.26.1`) — don't bump them casually. `fuzz/` is a separate workspace (nightly + libFuzzer), excluded from the main one.

## Conventions

- Conventional Commits are required; PR titles are validated by CI (types: `feat, fix, docs, style, refactor, perf, test, chore, ci, build`; `feat!`/`BREAKING CHANGE:` for breaking changes).
- No panics in library code — return `Result`. Public API gets doc comments with examples.
- The version lives only in the root `Cargo.toml` `[workspace.package]`. Bump with `scripts/bump-version.sh`; the canonical release path is GitHub Actions (`release-trigger.yml` dispatch → tag → `release.yml`).
- `migrations/` is append-only; new files follow `YYYYMMDDNNNNNN_name.sql`.
- `site/` is generated by MkDocs and auto-committed by the `docs.yml` bot — never hand-edit it. Edit `docs/` and expect a follow-up bot commit (`docs: ... [skip ci]`). Doc version banners must match the workspace version (enforced by `docs-consistency` CI).
- `cargo audit` ignores (RUSTSEC-2023-0071, RUSTSEC-2024-0436) are documented in `.cargo/audit.toml`.
- `ferrous-dns.db` at the repo root is a local test artifact — never commit it (`*.db` is gitignored). `ferrous-dns.toml` at the root is the canonical example config and belongs in the repo.

## Testing

- ~170 integration test files live per-crate in `crates/<name>/tests/`; shared fixtures are in `crates/tests/common/` (the test server binds `127.0.0.1:0` — no root or port 53 needed).
- Competitor/performance tests are `#[ignore]`d; they need external DNS servers (see `bench/`).

## Fuzzing

- Needs nightly (CI pins `nightly-2026-07-01`) + `cargo-fuzz 0.13.2`; 5 targets: `query_fast_path`, `response_lowercase_0x20`, `dnssec_records`, `proxy_protocol_v2`, `blocklist_text`.
- Crash policy: minimize with `cargo +nightly fuzz tmin`, add a regression test in `crates/infrastructure/tests/fuzz_regressions.rs` **before** fixing. CI fuzzes each target 60s per PR and it gates merges.

## Skills

- `/verify` — runs the full local CI gate (fmt-check, clippy with `-D warnings`, all tests, doc tests) and fixes failures at the root cause.

## Guardrails

- Direct commits to `main`/`master` are blocked by a PreToolUse hook in `.claudin/settings.json` — create a branch and open a PR instead.
- Edited `.rs` files are auto-formatted with `rustfmt --edition 2021` via a PostToolUse hook.
