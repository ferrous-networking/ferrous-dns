# Fuzzing

Ferrous parses bytes that arrive from the network, from anyone, with no
authentication in front of them. This directory holds the `cargo-fuzz` targets
that cover that surface.

## Running

Needs nightly (libFuzzer relies on `-Zsanitizer=address`):

```bash
rustup toolchain install nightly
cargo install cargo-fuzz --version 0.13.2 --locked

# one target
make fuzz TARGET=query_fast_path FUZZ_TIME=300

# every target, 60s each — what CI runs on a pull request
make fuzz-short
```

`make ci` does **not** run the fuzzers: the local gate stays on stable.

## Targets

| Target | Covers | Who controls the bytes |
| --- | --- | --- |
| `query_fast_path` | `dns::fast_path::parse_query` chained into `dns::wire_response::build_cache_hit_response` | any client that can send a UDP packet |
| `response_lowercase_0x20` | `dns::forwarding::response_validator::lowercase_owner_names` | the upstream resolver, or an off-path spoofer racing it |
| `dnssec_records` | `RrsigRecord::parse`, `DsRecord::parse`, `DnskeyRecord::parse` | a hostile signed zone |
| `proxy_protocol_v2` | `dns::proxy_protocol::read_proxy_v2_client_ip` | whatever speaks to the TCP/DoT listener behind a load balancer |
| `blocklist_text` | `dns::block_filter::compiler::parse_list_text` | the remote blocklist an operator subscribes to |

`query_fast_path` does more than look for panics. It runs a **differential
oracle** against hickory: whenever both parsers accept a packet, the fast path
and the slow path must derive the same cache key and the same record type. They
key the cache independently — `FastPathQuery::domain()` versus hickory's
`Name::to_utf8()` in `server.rs::handle_raw_udp_fallback` — so any disagreement
means one query can land under two cache entries, or two different wire names
under one.

It deliberately does *not* assert that hickory accepts everything the fast path
accepts: `parse_query` tolerates a truncated additional section on purpose, and
hickory rejects it.

Parsers that are crate-private in a normal build are reached through
`ferrous_dns_infrastructure::dns::fuzz_api`, a wrapper module compiled only
under the non-default `fuzzing` feature.

## Corpus

`fuzz/corpus/<target>/` is versioned and regenerated by `make fuzz-seeds`
(`fuzz/seeds.py`). CI layers a cached, fuzzer-grown corpus on top of it; the
nightly workflow runs `cargo fuzz cmin` before storing it again.

`fuzz/dict/dns.dict` gives libFuzzer the wire-format tokens (flag words,
QTYPEs, the OPT record, PROXY v2 signature, blocklist syntax). Its path is
relative to the repository root, where `cargo fuzz` runs.

## When the fuzzer finds something

1. Minimize it: `cargo +nightly fuzz tmin <target> fuzz/artifacts/<target>/<input>`
2. Add a named test with the minimized input to
   `crates/infrastructure/tests/fuzz_regressions.rs` — that file is the record
   of what the fuzzer has already caught, and it runs on stable.
3. Fix the production code, then keep the input in `fuzz/corpus/<target>/`.

## CI

- **Pull request** — `fuzz-short` in `.github/workflows/ci.yml`: one job per
  target, 60s each, on a pinned nightly (`FUZZ_NIGHTLY`), and it gates
  `ci-success`. Pinned because a blocking job must not break on an unrelated
  compiler regression; bump it deliberately.
- **Nightly** — `.github/workflows/fuzz.yml`: 30 minutes per target on floating
  nightly, uploads crashing inputs as artifacts. Being non-blocking, it also
  works as the canary that tells us a newer nightly is safe to pin.

## Known gaps

- **`crates/cli/src/server/dns/pktinfo.rs`** (34 of the project's 44 `unsafe`
  blocks) is *not* covered. It is `recvmmsg`/`sendmmsg` plumbing and a manual
  walk of the control-message chain: those bytes come from the kernel, not from
  the packet, so a `&[u8]` fuzz target never reaches them. Assurance for that
  code needs a different tool (a sanitizer run over the existing test suite).
- **TCP/DoT/DoQ length-prefix framing** (`crates/cli/src/server/dns/{tcp,dot,doq}.rs`)
  lives in the binary crate, which no other crate can depend on. Covering it
  means moving the framing into a library crate first.
- **OSS-Fuzz** is not wired up yet. The project qualifies (open source, network
  attack surface, Rust); worth doing once these targets have run against real
  corpora for a few weeks.
